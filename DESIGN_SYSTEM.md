# Design System Reference

> Filled in from the actual codebase (`src/index.css`, `src/components/Typography.tsx`, and usage across `src/pages/*.tsx` and `src/components/*.tsx`) as of 2026-08-24, with additions from a 2026-08-27 session (decorative-illustration pattern, `--nav-edge-w` wide-viewport behavior, two implementation gotchas) and a later 2026-08-27 pass that closed the last open button/spacing/card/icon inconsistencies (items 7–10 below). ## Colors

All defined as CSS custom properties in a Tailwind v4 `@theme` block in `src/index.css` (no `tailwind.config.js` — this project is CSS-first Tailwind v4). Tailwind's own default palette (e.g. `violet-300`, `red-*`) is also still used directly in a few spots alongside these tokens — see Inconsistencies.

- **Primary / brand accent (purple scale)**, darkest → lightest:
  `--color-purple-void: #241457` · `--color-purple-dark: #4c1d95` · `--color-purple-deep: #6d28d9` · `--color-purple: #7c3aed` · `--color-purple-mid: #8b5cf6` · `--color-purple-light: #a855f7` · `--color-purple-pale: #c4b4ff` · `--color-purple-highlight: #d8b4fe`
- **Background(s):**
  `--color-black: #08080c` (main page bg) · `--color-black-soft: #0c0c10` (cards / mockup chrome) · `--color-black-elevated: #2a2a30` (button surfaces) · `--color-black-ink: #070707` (text-on-light-page black, also used as a near-black overlay bg e.g. `bg-black-ink/85` on Contact)
- **Text (default):** `--color-white: #fdfbf6` (off-white/cream, not pure `#fff`) — almost always used at reduced opacity for hierarchy: `text-white` (headings, 100%), `text-white/85` (body), `text-white/70` (secondary body), `text-white/50` (muted/kicker), `text-white/40` (fine print)
- **Text (muted):** `--color-grey: #9ca3af` / `--color-grey-dark: #6b7280` (hover state) — used for scrollbar/tag-style neutral UI, not body copy (body copy uses white-opacity steps instead, see above)
- **Border:** no dedicated border token — borders are `border-white/10` or `border-white/15` (see Inconsistencies for which contexts use which), or a semantic color at reduced opacity (`border-success/50`, `border-danger/50`, `border-purple-pale/40|50`)
- **Success / Error / Warning:**
  `--color-success: #4a7c59` / `--color-success-bg: #a7f3d0` (Warning has no dedicated token — not used anywhere in the codebase)
  `--color-danger: #7c4a4a` / `--color-danger-bg: #7c4a4a` → `#fecaca`
  Pattern: the saturated tone (`success`/`danger`) is for borders/dots/icon fills on the tinted glass background; the pale `-bg` tone is reserved for *text* on that same background, since the saturated tone fails WCAG contrast there (used for "Point Forts" / "Point Faible" card headings on Fine Line).
- **Link:** `--color-link: #568cc2` (Fine Line "En savoir plus" underlined links)

## Typography

- **Font family (headings):** `--font-syne: "Neue Montreal", "Roboto", system-ui, sans-serif` — applied via the `font-syne` class name (historical name; the actual face is a self-hosted "Neue Montreal", not Syne). Weights available: 300/400/500/700, each with an italic. Used for H1–H3, section numbers, pull quotes.
- **Font family (body):** `--font-sans: "Roboto", system-ui, sans-serif` — set globally on `body`. Used for everything that isn't a display/heading element.
- **Base font size:** no explicit override on `html`/`body` — Tailwind/browser default `16px` (`1rem`) applies. In practice the most common *body copy* size is `Body1` (18px mobile → 20px desktop).
- **Scale** (from `src/components/Typography.tsx`, the canonical type-scale components):
  | Component | Mobile | Desktop (`md:`) | Weight/case | Use |
  |---|---|---|---|---|
  | `Display` | `text-5xl` / `leading-tight` | `text-7xl` / `leading-[72px]` | — | Home hero greeting only, ≤1 per site |
  | `H1` | `text-4xl` / `leading-tight` | `text-6xl` / `leading-[1.1]` | — | Page title, one per page |
  | `H2` | `text-4xl` / `leading-tight` | `text-5xl` / `leading-[48px]` | — | Section title, centered |
  | `H3` | `text-2xl` / `leading-tight` | `text-3xl` | — | Subsection/card title |
  | `H4` | `text-lg` | (same) | `font-semibold uppercase tracking-widest`, `text-purple-pale/70` | Large kicker, centered |
  | `H5` | `text-sm` | (same) | `font-semibold uppercase tracking-widest`, `text-white/50` | Small kicker |
  | `H6` | inherit | (same) | `font-semibold`, not uppercase | Compact card label |
  | `Body1` | `text-lg` / `leading-[1.55]` | `text-xl` | `text-white/85` | Primary paragraph |
  | `Body2` | `text-base` / `leading-6` | (same) | `text-white/70` | Secondary / list / supporting text |
  | `Micro1` | `text-sm` / `leading-5` | (same) | `text-white/50` | Smallest tier — captions, counters, fine print |
- **Body copy — the mapping (enforced 2026-08-27):** exactly three tiers, all via the components above, **no ad-hoc `<p className="text-lg/xl/2xl">`**. `Body1` = any real paragraph. `Body2` = list items, meta, supporting detail under a label. `Micro1` = captions / counters / the smallest legible text. There is **no `Micro2`** — it was `text-xs` / `white/40` (3.7:1, below WCAG AA) and unused; removed. If a genuine fine-print tier is ever needed, add it at `white/55` or darker-safe.
  - `Body1` line-height is unitless **`leading-[1.55]`** (was `leading-7` / 28px, which is a tight 1.40 once the size bumps to 20px at `md`; 1.55 gives ~31px there, ~28px on mobile — unchanged).
  - **Case-study section prose uses `.case-prose`** (`src/index.css`): `max-width: 60ch; margin-inline: auto; text-align: left`. Replaces the old `w-full text-center` pattern on section-intro `<Body1>`s, which ran 84–109 characters/line at ~984px wide and centred (both readability anti-patterns). `60ch` lands ~70–75 real chars/line for Roboto at 20px — the `ch` unit overshoots for a proportional face, so this is *not* 60 characters. The block still centres under its (centred) `H2`; only the text goes left.
- **Font weights used:** `300` (font-light, common on body copy for a lighter feel), `400` (default), `500` (font-medium, occasional labels/links), `600` (font-semibold, all kickers/H4/H5/H6), `700` (font-bold, rare — e.g. contact item labels). No `900`.
- **Line height:** mixed — Tailwind relative utilities (`leading-tight`, `leading-6/7/8/9/10`) **and** arbitrary pixel values (`leading-[72px]`, `leading-[56px]`, `leading-[48px]`, `leading-[1.1]`) are both used, sometimes for the same element at different breakpoints (e.g. `H1`'s own `md:leading-[1.1]` vs. page-level `H1` overrides using `md:!leading-[56px]`). See Inconsistencies.

## Spacing scale

- **Base unit:** `4px` / `0.25rem` — standard Tailwind default scale, no custom spacing tokens defined.
- **Scale actually in use** (from `gap-*`, `p-*`, `px-*/py-*` across the codebase): `1, 1.5, 2, 3, 4, 5, 6, 8, 10, 12, 14, 16, 20, 24` (×4px = 4px…96px). Most common: `gap-4`/`gap-6`/`gap-8` for stacks, `p-6`/`p-8` for card padding, `px-6 py-2` for pill buttons, `px-4 py-2` for smaller nav/filter pills.
- **Page-section wrapper** (the pattern for every top-level section/page — `ContactPage.tsx`'s lone `px-6 py-16 … md:py-24` deviation was normalized on 2026-08-27): `p-8 md:py-16 md:px-[var(--nav-edge-w)]`, where `--nav-edge-w` is a JS-measured CSS var (width of the nav's edge content) kept in sync via a `ResizeObserver` in `NavBar.tsx` — not a static token. **Gotcha (found 2026-08-27):** this value keeps growing well past its ~96px "default" at wide viewports — it's computed to align section content with the navbar's actual edge, not capped to a fixed max, so it measured **228px per side at a 1536px viewport** in practice. A section relying on `--nav-edge-w` for its horizontal padding can end up with far less usable inner width than expected on large screens; any section whose content needs to actually fill the available row (e.g. a `flex` row with a `flex-1` text column) should consider a fixed `px-*`/`lg:px-16`/`xl:px-24` override instead of the shared var if it's fighting for space.

## Border radius

Consistent hierarchy, no stray values:
- **Small:** `rounded-lg` (`0.5rem` / 8px) — lightbox/video modal media only (one outlier context; see Inconsistencies)
- **Medium:** `rounded-xl` (`0.75rem` / 12px) — images, image-crop containers, small icon tiles
- **Large / card:** `rounded-2xl` (`1rem` / 16px) — the standard content-card radius (`border border-white/15 bg-white/5 p-6 backdrop-blur-sm rounded-2xl` is the de facto card component, repeated ~30 times across `FinelinePage`, `OrealPage`, `AngryBirdsPage`)
- **X-Large / outer container:** `rounded-3xl` (`1.5rem` / 24px) — page-level outer wrappers (ContactPage form block, ProjectsPage cards, Projects carousel cards, success/danger callout cards)
- **Pill:** `rounded-full` — all buttons, nav items, dots, avatar/icon circles

## Shadows

**Consolidated into 3 shared tokens (2026-08-24)**, defined as parameterized formulas in `src/index.css` — `.shadow-glow` (ambient purple light), `.shadow-lift` (dark elevation), `.shadow-glass-card` (4-layer inset+ring+glow recipe). Every usage overrides the token's custom properties (`--glow-*`/`--lift-*`/`--glass-*`) via inline `style`, not a Tailwind arbitrary-property class — Tailwind's generated utilities live in `@layer utilities`, and this file's plain CSS is unlayered, so unlayered always wins regardless of source order, meaning a `[--glow-blur:10px]` class can never actually beat the token's own default. `.shadow-glow` also has a `:hover` rule using `var(--glow-blur-hover, var(--glow-blur))`-style fallbacks, so a hover-glow instance sets both the base and `-hover` custom properties inline and the CSS handles the transition.

Two elements compose two tokens on one box-shadow (photo-frame = `.shadow-lift.shadow-frame` adds an inset top highlight; the active carousel card = `.shadow-glass-card.shadow-lift` stacks both) via a `--shadow-*-layer`/`--shadow-*-layers` custom property each token exposes, referenced by the composing rule.

Every migration was verified by comparing `getComputedStyle(...).boxShadow` against the original literal formula resolved the same way — all 12 usages match byte-for-byte except one deliberate normalization: the active carousel card's 5th layer used a plain `rgba(0,0,0,.4)` instead of `color-mix(black-ink, ...)` like every other dark shadow; normalized to `color-mix(in srgb, var(--color-black-ink) 40%, transparent)` (imperceptible, `#070707` vs `#000000`).

`Tools.tsx`'s `shadow-sm` and the nav dropdown's `.purple-glow` were left as-is — both are already correctly-named, single-purpose tokens, not one-offs.

**Left bespoke, not tokenized:** `OrealPage.tsx`'s video-équipe hero frame (`0 0 50px` outer glow + a 2nd inset-ambient layer) — a 2-layer recipe unique to that one element, not reused anywhere else.

## Buttons

**There is no shared `<Button>` component.** `src/components/PillButton.tsx` exists and looks like one, but it's only imported in `FinelinePage.tsx`. The visually-identical primary CTA in `Hero.tsx` and `Contact.tsx` each hand-roll the same `className`/gradient/shadow inline instead of using it — three independent copies of the same button markup.

### Variants (as actually rendered)
- **Primary CTA pill** (`Hero` "Voir mes projets", `PillButton.tsx`) — `rounded-full px-6 py-2`, background `linear-gradient(135deg, var(--color-purple-light) 0%, var(--color-purple-deep) 100%)`, white text, glow shadow (see Shadows). Used for: main calls to action, external links (CV, Fine Line site).
- **Primary CTA pill, dark tone** (`Contact.tsx` "Contactez-Moi", via `<Button tone="dark">`) — identical shape/padding to the purple primary, but background `linear-gradient(135deg, var(--color-black-elevated) 0%, var(--color-black-soft) 100%)`, a `border border-white/15` hairline, and the `shadow-glow` recoloured to `--color-black-ink` at 55% opacity (a dark halo instead of a purple one). **This is now a real, documented `tone` prop on `Button` (`'purple'` default | `'dark'`), primary-only.** It exists for exactly one reason: a purple-gradient button on the purple "Travaillons ensemble !" section has almost no figure-ground contrast (verified in-browser 2026-08-27). Do not add more tones or use `dark` anywhere the background isn't a saturated purple field.
- **Ghost / nav pill** (`NavBar` items, `Footer` links, `CaseStudyNav` back-to-projects link) — `rounded-full px-4 py-2`, transparent background, `text-white/70` → `hover:text-white` or `hover:bg-white/10`. `NavBar`'s active-route state additionally gets `bg-purple-mid/45 text-white` (the only button variant with a true "active/selected" state). The desktop `<nav>` *container* that holds these items uses the shared `.glass-dark` material (85%-opaque black + `blur(20px)` + `white/10` hairline) so scrolling content doesn't show through it — was `bg-white/5` until 2026-08-27, see Inconsistency 15.
- **Filter/toggle pill** (Fine Line lightbox playback-speed selector) — `rounded-full border px-4 py-2 text-sm`; selected = `border-purple-pale/70 bg-purple/50 text-white`, unselected = `border-white/15 text-white/50 hover:text-white`.
- **Icon-only circular button** — two deliberately distinct families:
  - **Overlay controls** (`Lightbox` close/prev/next, `VideoModal` close) — bare (`opacity-80 hover:opacity-100`, no background/border), sitting on a dark scrim. **Uniform as of 2026-08-27: `size-14` hit target, `size-8` glyph** for every control in this family (Lightbox's prev/next were `size-11` before and were bumped to match its close button + `VideoModal`).
  - **In-page glass icon button** (`Projects.tsx` carousel arrows) — a full `glass-dark` circle, `size-11` hit target, `size-5` glyph, `border-[1.5px] border-purple-pale/50` + glow shadow. Left intentionally lighter-weight and smaller-glyph than the overlay family: it has visible button chrome (the overlay controls don't), so a ~45%-of-button glyph reads correctly where a bare 32px glyph would not. It's the only instance of this family.
- **Destructive:** not applicable — no destructive actions exist in this portfolio site.

### Sizes
Only one size is ever used per variant — there's no small/medium/large system:
- Primary/nav pills: padding `px-6 py-2` (primary CTA) or `px-4 py-2` (nav/filter), text size inherited from `Body1` (`text-lg md:text-xl`) for the CTA, `text-base` (nav) or `text-sm` (filter pill, CaseStudyNav back link).
- Icon buttons: overlay-control family = `size-14` button / `size-8` glyph (Lightbox + VideoModal); in-page glass family = `size-11` button / `size-5` glyph (Projects arrows only). See "Icon-only circular button" above.

### States (inconsistent across buttons — see Inconsistencies)
- **Default:** as above per variant.
- **Hover:** `hover:-translate-y-0.5` (CTA pills, lift effect) vs. `hover:text-white`/`hover:bg-white/10` (nav pills, color-only) vs. `hover:opacity-100` (icon buttons) — three different hover strategies with no shared rule. Transition is `transition-all duration-300` almost everywhere (a couple of `duration-200` and one `duration-500` outlier).
- **Active/pressed:** not implemented anywhere (no `:active` styling on any button).
- **Focus:** **not implemented anywhere.** Zero occurrences of `focus:`, `focus-visible:`, `outline`, or `ring-` in the entire `src/` tree — no button, link, or the two real `<button>` elements (`NavBar` dropdown toggle, `Lightbox` controls) has a visible keyboard-focus indicator. This is a real accessibility gap, not just a style inconsistency.
- **Disabled:** not implemented anywhere — no button in the site is ever disabled, so no disabled styling exists to standardize.
- **Loading:** not applicable — no async button actions exist.

## Other components to keep consistent

- **Inputs / form fields:** none exist. `ContactPage.tsx` is a static list of `mailto:`/`tel:`/external links, not a form — there is nothing to standardize here yet.
- **Cards:** the standard is `rounded-2xl border border-white/15 bg-white/5 p-6 backdrop-blur-sm` — **flat `p-6`, no responsive step-up** (tighter cards drop to `p-4`; the two genuinely-large Fine Line cards use flat `p-8`). OrealPage/AngryBirdsPage had drifted to `p-6 md:p-8` on ~13 cards during an earlier propagation; that `md:p-8` was removed on 2026-08-27 so every case study matches Fine Line. `md:p-8` no longer appears anywhere in `src/`. Two semantic variants layer on top: success (`border-success/50`, `rounded-3xl`, `backdrop-blur-[20px]`) and danger (`border-danger/50`, same shape) for Fine Line's Point Forts/Point Faible cards. Outer page-level containers step up to `rounded-3xl border border-white/10` (slightly lower border opacity than inner cards' `/15`).
- **Navigation / links:** underlined inline links use `text-link` (`#568cc2`) with `underline decoration-white/30 underline-offset-4`; nav pills covered under Buttons above.
- **Icons:** no icon library — every icon is a hand-written inline `<svg>` (e.g. `CaretDownIcon`, `ArrowUpRightIcon` in `NavBar.tsx`; `ArrowIcon`, `CloseIcon` in `Lightbox.tsx`). Consistently `viewBox="0 0 24 24"`, `strokeWidth="2"`, `strokeLinecap/Linejoin="round"`, `stroke="currentColor"` (so they inherit text color) — sized via Tailwind `size-*` utilities on the wrapping element (`size-3.5`, `size-4`, `size-6`, `size-8` all appear; no fixed icon-size scale).
- **Decorative background illustrations:** every hand-drawn illustration on the page (`about-canoe-sketch.png`, `about-clapperboard.png`, `about-wireframe-sketch.png`, the France/Lebanon map art, etc.) follows the same recipe: source PNG is black line art on a transparent background, rendered with `opacity-25 invert` (the `invert` filter flips black→white/light-grey so it reads correctly against the page's dark background) plus `pointer-events-none` since these are always non-interactive. **Reference implementation:** `AboutPage.tsx`'s "Un Tournant Décisif" section (as of 2026-08-27) — at `lg:` and up, three independent PNGs (`about-france-map.png`, `about-lebanon-map.png`, `about-route-line.png`) flank/overlay the heading+paragraph: France and Lebanon sit as ordinary flex siblings on either side of the text column, while the route-line/plane image is `absolute`-positioned above the heading (deliberately stretched with a non-proportional explicit `width`/`height`, i.e. intentionally distorted, not `h-auto`). Below `lg` (tablet and mobile), all three collapse to a single pre-composed image (`about-liban-paris-map.png`, kept in `src/assets/` for this purpose) shown as one block above the text — simpler than trying to lay out 3 independent images in a narrow column.

## Implementation gotchas

Technical footguns hit while building the pages above — not style rules, but worth knowing before touching similar layouts:

- **`max-w-none` is required on any absolutely-positioned `<img>` sized larger than its containing block.** Tailwind's Preflight sets `img { max-width: 100% }`. For a normal in-flow image this is harmless, but an `absolute`-positioned image's containing block is its nearest `position: relative` ancestor — if that ancestor is narrower than the image's intended `width` (e.g. a decorative image meant to overhang a narrow text column), the `max-width: 100%` reset silently caps it back down to the ancestor's width, with no visual error, just a smaller image than the CSS width class says. Always pair an oversized `absolute` image with `max-w-none`.
- **`overflow-hidden` on a section will clip a decorative element that intentionally pokes outside its sibling via a negative offset**, unless the section's own padding is large enough to contain it. If an `absolute`-positioned element uses e.g. `-top-[180px]` to sit above a `relative` sibling, the section wrapping both needs at least that much padding-top (plus a small buffer) — otherwise the section's own `overflow-hidden` (used site-wide to contain other absolutely-positioned art) will silently crop the top of it. This has to be recomputed by hand whenever the offset changes.
